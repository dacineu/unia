# Commercial use, support, and licensing

## The short version

**You do not need to contact us to use unia commercially.** The reference
implementation is MIT licensed, and MIT grants exactly that: use, copy, modify,
merge, publish, distribute, sublicense, and sell, including for commercial
purposes, in any field, with only the requirement of preserving the copyright
notice and license text.

That is deliberate. Permissive licensing is how the project gets adopted, and
adoption is what makes the work worth something. A restrictive license would
raise the price of every use and shrink the thing it is trying to build.

What is **not** granted by MIT, and what we therefore discuss separately:

- the `unia`, `unia-OS`, `UPA`, `DU-UUID` and `.ure` names and marks, which are
  not licensed and are governed by [`TRADEMARK.md`](./TRADEMARK.md)
- warranty, support, uptime commitments, or indemnification
- private forks, bespoke features, or consulting
- any claim that the specification in [`docs/SPEC.md`](./docs/SPEC.md) is an
  official standard, or that this project is affiliated with or endorsed by any
  standards body

## What can be discussed

| Engagement | What it means |
| --- | --- |
| **Support and SLA** | Response targets, maintenance, and a supported version line. The most common first engagement. |
| **Consulting** | Architecture review, integration work, or embedding `.ure` in an existing agent system. |
| **Private development** | Features built for one customer under NDA, before or instead of upstreaming. |
| **Dual licensing** | A negotiated license where MIT does not fit your compliance requirements. Only possible for contributions covered by a DCO sign-off. |
| **Specification work** | Help making `.ure` interoperable with an implementation you already have. |
| **Trademark permission** | Written consent to use the unia name in a product, or a coexistence arrangement. |

All of these start the same way: **<dacineu@proton.me>**.

## What we are actually optimising for

unia is early. The honest goal is not to maximise licensing revenue, it is to
make the work used widely and kept correct. The ordering that achieves that:

1. **Adoption.** MIT, low friction, no CLA, no feature gates, no enterprise
   edition. If it is not being used, none of the rest matters.
2. **Correctness of the specification.** A `.ure` ecosystem only works if
   independent implementations interoperate. That means a precise, versioned
   spec, not a clever one.
3. **Sustainability.** Support, and eventually an entity to hold the IP so
   contributions, trademarks, and obligations have a legal home.

If you want to help with any of that and are not a commercial counterparty, the
same address works. See also [`CONTRIBUTING.md`](./CONTRIBUTING.md).

## A note on independent implementations

If you are building a `.ure` implementation without using our code, you do not
need a licence and you do not need permission, provided you do not use the
trademarks. This project would rather be a useful standard than a toll booth. If
your implementation is good, tell us about it so it can be listed in the
ecosystem section of the README.
